# Публикация комплекта ISCC

Публикуется отдельный комплект исходников и инструкций. Установка в принимающую панель выполняется по [AGENT_INSTALL.md](AGENT_INSTALL.md), обновление — по [UPDATE.md](UPDATE.md). Для публикации нужна учётная запись с правом записи в выбранный репозиторий.

## Проверить выпуск

Из корня распакованного комплекта выполните:

```sh
python3 prepare.py --verify
npm test
python3 -m unittest discover -s tests -p 'test_*.py'
```

На Windows допустимо `py -3`. Повторите две команды тестов в `components/level-renderer`. Итоги и ограничения укажите в VALIDATION.md. Проверьте инструкции, выбор функций, цепочки импортов, контрольные суммы и состав архива. В архив включаются только пути из manifest.json и сам manifest.json. После правки файла контрольная сумма пересчитывается при подготовке выпуска.

## Загрузить исходники

Для существующего репозитория сначала получите его текущую основную ветку и сравните изменения. Выполните обновление в отдельной ветке `codex/update-0.4.0`, сохранив независимые правки репозитория. Проверьте итоговый diff, создайте коммит и отправьте ветку. Затем объедините её обычным для репозитория способом. Не перезаписывайте чужие коммиты и не используйте принудительную отправку.

Для нового репозитория корнем служит содержимое распакованного комплекта. Публикуются инструкции, исходники, тесты, `ci/`, `.gitignore` и manifest.json. Рабочая папка `local/` не публикуется. Историю полного проекта панели в репозиторий дополнения не переносите.

Пример отправки подготовленной ветки через уже подключённый GitHub CLI:

```sh
git push origin codex/update-0.4.0
gh pr create --base main --head codex/update-0.4.0 --title "ISCC 0.4.0" --body-file CHANGELOG.md
```

`ci/check.yml.example` — шаблон проверок Linux/Windows. Для активации отдельно проверяют подходящую конфигурацию и добавляют `.github/workflows/check.yml`. Публикация комплекта не требует автоматически активировать этот шаблон.

## Создать выпуск с архивом

После объединения зафиксируйте точный коммит, из которого подготовлен архив. Проверьте совпадение его дерева с manifest.json и архивом. Для существующего тега сначала изучите опубликованный выпуск; не заменяйте его файлы молча.

Пример для нового тега, где `COMMIT_SHA` заменяется проверенным коммитом, а путь архива — фактическим путём:

```sh
gh release create v0.4.0 ../ISCC-Addons-0.4.0.zip --target COMMIT_SHA --title "ISCC 0.4.0" --notes-file CHANGELOG.md
```

Откройте опубликованный выпуск и проверьте тег, коммит, имя архива, размер и SHA256. Одна ссылка для получателя ведёт на страницу выпуска с архивом. README ведёт к UPDATE.md, START_FOR_AGENT.txt и инструкции добавления инструментов. Статус «опубликовано» не означает, что обновление установлено на компьютере получателя.

## Передать автору ISCC

Для интеграции в исходную ISCC подготовьте отдельную ветку и PR с адаптированными узкими изменениями. Предложение отрисовщика и предложение торгового исполнителя имеют разный состав. Не включайте BML/SML в PR, который заявлен только как отрисовщик уровней. Ссылка на комплект и список функций позволяют автору выбрать, что переносить в основную панель.
