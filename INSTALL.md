# Установка через агента

1. Прочитайте `README.md`, выберите компоненты в `SETUP.html`, сохраните план в ignored `local/selection.json`.
2. Агент локально определяет установленную ИСКК и её исходники. Если панели нет, скачивает последнюю стабильную версию [автора](https://github.com/iziziz-indepstate/indepstate-cc/releases/latest), сверяет конкретный тег/коммит и создаёт рабочий проект. На момент подготовки базой сравнения служит v1.2.0. Не заменяйте установленную панель целиком версией владельца дополнения.
3. Выполните `python3 prepare.py --source /path/to/iscc --plan local/selection.json`. На Windows можно использовать `py -3`. Команда проверяет manifest, хеширует точки интеграции и создаёт `local/prepared-*` с отчётом и выбранными исходниками. Она не меняет приложение, приёмник, настройки и торговые журналы.
4. Агент сравнивает `payload/src/app/services/` с существующими сервисами. Подключает `module/index.js` или переносит эквивалентные узкие изменения: расчёт плана, `createChunkAdmission`, клиент набора и восстановление. Полные файлы с независимыми доработками не заменяются автоматически. Старую уже установленную функцию сначала сравнивают с новой; два координатора одного журнала не запускаются.
5. Для интерфейса используйте `reference/renderer-functions.js.txt`, `reference/main-entry-handlers.js.txt` и `reference/mt5-service-manifest.js.txt` как материал сравнения. BML/SML доступны на индексной карточке, связанной с LT. Штатные LB/LS и независимые функции панели сохраняются. Пример вызова — `module/index.js`; сохранённый `chunkPercent` читается из настроек Level Orders, множитель новых входов равен 1.
6. Для текущего режима нужны `independent-account-engines-v5`, `entry-initial-sizing-only-v1`, `hybrid-market-limit-v1`, `hybrid-position-protection-v1` и остальные запрошенные клиентом возможности. `payload/vps/` содержит ядро и обязательные `entry_wait_totals.py`, `broker_opening_evidence.py`. Если адаптера MT5 нет, сначала интегрируйте и проверьте его транспорт. Пути, счета, серверы, токены и сертификаты задаются только локально. Контракт риска, интерфейса и управления описан в `INTEGRATION.md`.
7. Существующие параметры и журналы сохраняются на своих местах. Автоматическая резервная копия в комплект не входит. Между сравнением и записью агент повторно сверяет хеши изменяемых файлов; конфликтующие изменения сначала объединяет. Подготовка этого комплекта не разрешает останавливать торговлю или менять действующие заявки получателя.
8. Запустите `node --test tests/*.test.js` и `python3 -m unittest discover -s tests -p 'test_*.py'` из комплекта. Затем выполните значимые тесты принимающей панели, обновите её lockfile и соберите приложение. Пакет не запускает команду release/publish.
9. В принимающей среде проверьте демо-сценарии BML/SML: внутри/вне зоны, дробный процент, 100%, частичное исполнение лимитки, гонка отмены, устаревшая котировка, потеря ответа, перезапуск, общий SL, отмена до принятия, один и несколько счетов. Проверьте частичное закрытие выбранной позиции в лотах/процентах и по цене. Фиктивный терминал не заменяет проверку конкретного брокера.

Дополнение остаётся выключенным до завершения интеграции. Нельзя сообщать об установленной готовой функции только по наличию кнопок или скопированных файлов. Итоговый локальный отчёт должен указывать сборку, проверенные компоненты и оставшиеся ограничения.
